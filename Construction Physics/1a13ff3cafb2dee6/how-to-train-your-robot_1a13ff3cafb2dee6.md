You feed a model some set of inputs, you compare the model’s output to the actual, correct output, and you use the difference between the two to modify the parameters of the model to reduce this difference via some flavor of gradient descent. One chunk of text can thus generate many training examples by feeding the model different portions of the text. To train a robot, an example is typically some sort of recording of a task being accomplished or attempted. There are a variety of different methods used to create these recordings and turn them into training data. Historically, one of the most common methods for creating these recordings is called “teleoperation.” With teleoperation, a person manipulates some controls that are directly connected to a robot, and uses them to move a robot through some particular task (folding a shirt, picking up and moving objects, and so on). The image below, for instance, shows a person teleoperating a pair of robot arms, using them to pour water from a pitcher into a glass. As the person performs the task, data of the robot’s state is recorded, along with images from cameras that are recording the task (often mounted to the robot itself), which are combined to create a training example. An example might consist of feeding a model some data on the robot’s state and what the cameras can see at some particular point in the sequence. The model will try to predict what the next robot actions are (in the form of something like joint angles), and then compare that to what the actual actions were. The biggest one is probably expense: to get the data, you need to have an actual robot, along with a person to sit there and manipulate it, which makes it hard to scale this method to produce very large amounts of data. Another drawback is that it’s somewhat clunky for a person to control a robot this way; they often can’t get any sort of tactile feedback from the object being manipulated to guide their motions, so this won’t necessarily produce really good data on dexterous manipulation. The clunkiness can also make it hard to collect good teleoperation data, and as I understand it, only a fraction of total teleoperation data collected ends up being useful for training. It’s also possible to generate training data using an existing robot by having it move around on its own, recording its actions, and using some sort of system to categorize these behavioral sequences as successful or not. The biggest one is that the quality of the data it produces is a function of the accuracy of the simulation. For some things, such as locomotion (having a robot move through some physical space), simulation is fairly accurate, because the behavior is mostly well-characterized enough that we can represent it digitally. So you can train a quadruped robot to navigate some terrain, or a bipedal robot to dance, or a drone to fly along some path in simulation, and the simulated environment will be a reasonably good approximation of the real world. But for things such as object manipulation (particularly for soft or deformable objects), it’s much harder to build a simulation that accurately captures real-world behavior, and using it as a source of training data is much more difficult. How much data we actually need, however, seems to be something of an open question. If we don’t care about generalization, and only want to train robot models to perform various specific tasks, the data requirements might be substantially less. Alternatively, it might turn out that frontier general AI models like Fable or Astra are extremely capable robot controllers after being fed a comparatively small amount of robotic training data; some folks are already predicting that special-purpose robot AI models might get replaced with more generic AI models. Likewise, we might find robotic AI model architectures that are much more sample efficient — learning much more from each training example — than current models. On the other hand, it could be the case that moving around and manipulating objects in the real world is a fundamentally more difficult task than manipulating text on a computer, and that models require a lot more training to become competent at this real-world behavior. Small errors in generated text, for instance — misspellings, or slightly wrong word choice — don’t necessarily compromise the text as a whole, but when you’re manipulating objects a single tiny positioning error can be the difference between success and complete failure.
