I’ve been building more, posting less lately. Why? AI is moving incredibly fast, and the metagame is moving even faster. The only way I’ve been able to make sense of it is by building to think [ https://substack.com/redirect/191dd9eb-5b4c-463d-aa3d-490dd300e23e?j=eyJ1IjoiOG81NG4ifQ.6oeetudtJEh-zO1onUJvtadWEdbodFIw0h4xbugrh1o ].
In the last 4 months, my workflow has changed repeatedly, from code completion, to coding agents, to multiple agents in multiple worktrees, to agent factories. I’m about 3x faster, and I suspect I can ratchet this up to 10x with factories. At the same time, I am keenly aware that I am just a hair’s breadth ahead in the Red Queen Race [ https://substack.com/redirect/43cd5b6e-9789-47f9-a13f-ea2d01713887?j=eyJ1IjoiOG81NG4ifQ.6oeetudtJEh-zO1onUJvtadWEdbodFIw0h4xbugrh1o ]. I can feel selection pressure nipping at my heels.
Now, here, you see, it takes all the running you can do, to keep in the same place. If you want to get somewhere else, you must run at least twice as fast as that!
(The Red Queen in Lewis Carroll’s Through the Looking-Glass)
This is what it feels like to live through disruption [ https://substack.com/redirect/707e3103-6f74-4eeb-9e8c-210496ea1787?j=eyJ1IjoiOG81NG4ifQ.6oeetudtJEh-zO1onUJvtadWEdbodFIw0h4xbugrh1o ]. The situation gets into your OODA loop [ https://substack.com/redirect/3bc7d0ef-5414-4bcb-8d15-7e07bf08e508?j=eyJ1IjoiOG81NG4ifQ.6oeetudtJEh-zO1onUJvtadWEdbodFIw0h4xbugrh1o ] and it’s hard to stay oriented. You just keep moving as fast as you can.
This poses a challenge when writing. See, when I write, it is usually to capture a speed run through an idea maze. For example, I explored the idea maze around decentralized software for about 5 years, and came away with a map of paths that work (user-owned keys and hash addressed data [ https://substack.com/redirect/dda8a9f3-2b3c-46b8-9d44-158bb956e1a7?j=eyJ1IjoiOG81NG4ifQ.6oeetudtJEh-zO1onUJvtadWEdbodFIw0h4xbugrh1o ]), and paths that seem like they should work, but are dead-ends (flat p2p network topologies [ https://substack.com/redirect/2e4e2ff5-5306-4dc7-a25c-52078d6a97c0?j=eyJ1IjoiOG81NG4ifQ.6oeetudtJEh-zO1onUJvtadWEdbodFIw0h4xbugrh1o ]). It took a long time to map these paths. They are highly compressed models of the problem space.
I struggle to develop this kind of highly-compressed model for AI. A model is a map of the parts of a system that aren’t changing. But during a disruption, everything changes. Value chains dissolve and are reformed [ https://substack.com/redirect/43e45a2d-3ebc-42bf-8a62-119af58a058a?j=eyJ1IjoiOG81NG4ifQ.6oeetudtJEh-zO1onUJvtadWEdbodFIw0h4xbugrh1o ], and the competitive landscape goes from clear to chaotic [ https://substack.com/redirect/9aacd553-fced-491b-9f56-c03f9870bf96?j=eyJ1IjoiOG81NG4ifQ.6oeetudtJEh-zO1onUJvtadWEdbodFIw0h4xbugrh1o ]. Complex models are overfitted for chaotic environments, and anyway, they get obsoleted faster than you can build them.
God is very cruel. He only gives us data about the past.
-Paraphrasing Clayton Christensen [ https://substack.com/redirect/d4a1a789-b9da-4d44-a449-89b8901e63f5?j=eyJ1IjoiOG81NG4ifQ.6oeetudtJEh-zO1onUJvtadWEdbodFIw0h4xbugrh1o ]
When data is really bad, you should use the simplest model at hand. When data is very good, you can use complicated models.
-SFI Podcast Apr 6, 2020 [ https://substack.com/redirect/0fda74a4-8260-416f-bbc3-74ae853b925d?j=eyJ1IjoiOG81NG4ifQ.6oeetudtJEh-zO1onUJvtadWEdbodFIw0h4xbugrh1o ]
When things are moving this quickly, we don’t want a model, we want a log. It’s the simplest model that could possibly work [ https://substack.com/redirect/0e40fb85-43f2-4880-9e97-62e029dfcf97?j=eyJ1IjoiOG81NG4ifQ.6oeetudtJEh-zO1onUJvtadWEdbodFIw0h4xbugrh1o ]. Just lines of timestamped comments, one after the other: “this happened, then this happened, then this happened”. No higher-level analysis. In software, we log everything that happens during program execution, because logs are invaluable when things spin out of control. We can comb through the log to find patterns, and begin to form higher-level hypotheses about what is happening.
I think this is the right level of sense-making for the moment. It’s time to drop to log level. You’ll see me shifting away from essays, toward work in progress, technical posts, fragmentary ideas, and raw logging.
In/out:
Out: essays.
In: logging what I learn, as I learn it.
Out: theory.
In: practice.
Out: good writing.
In: good ideas.
Out: “having an audience”.
In: hoarding things I know how to do [ https://substack.com/redirect/fd6f0b52-7f73-46ae-8189-4f50101ff784?j=eyJ1IjoiOG81NG4ifQ.6oeetudtJEh-zO1onUJvtadWEdbodFIw0h4xbugrh1o ].
